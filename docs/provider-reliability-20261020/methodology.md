# 连接可靠性与未知用量：P0 阶段

本阶段只处理上轮规划中的前两项：连接可观测、整批发送前熔断，以及未知用量/发送未确认/实际预算阈值的区分。不修改上游测试收集、原有测试、修复提示或旧评测分母，不追加历史 Bug 修复实验。后续原生测试收集和测试语义改进另作阶段。

## 连接诊断

遍历最多 8 层异常因果链，仅记录允许列表中的类型和 connect/read/write/pool/proxy/protocol/response/unknown 阶段。自定义异常类名、异常文字、请求 URL、请求头和提供方响应正文不进入新增诊断。异常阶段不是服务端根因、发送成功或计费结果证明；流式请求失败标记完成未确认，不能凭 SDK 外层 APIConnectionError 推断具体原因。

每个实际 invoke 尝试有本地产生的 attempt_id、开始时间、耗时、结果及用量是否完整；调用间隔另记。启用任务预算或批量熔断时，SDK 隐式重试关闭，每次显式尝试先过发送准入，预算开启时先持久预留。发送前本地配置失败仍是已知零用量，不误标模型用量未知。请求号由本机产生，不复制不可信异常文本。

## 整批熔断

新增 `REPOPILOT_EVALUATION_PROVIDER_FAILURE_THRESHOLD=3`，仅用于 live 批量评测；0 显式关闭，可用于复现旧协议。默认 Mock 批量评测不启用该门控，也不称真实模型验证。

同一批次、所有案例/模式/策略共享一个发送门控。按完成顺序累计相同“失败类别 + 阶段”：连接、超时、限流、服务不可用和响应缺少用量；成功或不同签名重置当前连续数。认证拒绝立即熔断。阈值达到后门控保持打开，不自动复位或重发；并发中此前已准入的请求仍可结束和记账，后续成功不解除已打开状态。

发送检查位于每次模型 invoke 前，包含同一任务的后续节点及解析重试。门控已打开时，不再准入新请求或为其预留任务请求额度。尚未创建的单元记为 not_run；已经创建但被门控拦下的任务记为 batch_paused，候选和已有证据保留，API 不允许在新服务实例上绕过终止状态继续。

所有计划单元保留，未执行不是模型失败，已知零请求/零用量不计为用量未知。历史评测严格成功率仍用全部计划任务作分母；通用评测额外提供 planned_ready_and_accepted_rate，同时保留旧条件统计，不把较小条件分母冒充主成功率。熔断信息和原因进入报告及本地快照。

证据回调失败会在本进程中停止新准入，且不丢弃刚完成响应的已观测用量。个体任务请求账本仍持久化；批次门控是进程内对象和快照，不是跨进程全局协调器或可恢复调度日志。非空输出目录拒绝重跑；本阶段未实现进程崩溃后的批次恢复。独立 API 服务任务不会自动共享评测器的批次门控。

## 停止原因与兼容性

保留既有粗粒度 execution_status=budget_exhausted 和 resource 字段，避免破坏保存的任务及客户端；新增受 Pydantic 约束的 budget_failure.kind：limit_reached、usage_unknown、dispatch_uncertain、ledger_integrity。预算查询增加 usage_status，界面分别解释实际预算限制、用量未确认、执行未确认和账本无法核验。

旧任务不重写，界面从已有 resource/用量完整标记推导显示原因。任务预算启用时，未知用量或未完成预留继续阻止后续工作；改变服务器预算开关不能解除已保存任务的账本和终止状态。预算关闭的既有工作流保持旧契约，不宣称其有完整计费保护。已观测 Token 是准入阈值，不是账单或单响应绝对硬上限。

## 验证协议

先做受控故障注入，再验证新 wheel 全套，最后冻结最多 12 次真实生成探测。受控测试使用实际 SDK 与注入 HTTP 传输，不是真实 LLM：覆盖连接、读取超时、代理、协议、流式中断、缺失用量、预算拒绝、并发已准入请求、重启禁止重放及证据写入失败。目标仓库代码不在宿主机执行；完整回归显式启用真实 Docker。

新 wheel 全部 114 个包内应用文件与源码、安装目录逐字节核对；83 个阶段前已有测试/辅助文件与 982979e 比较，保持不变。本阶段只新建两个故障控制测试文件。验证目录的演示 auth.py 修复为 401，同时故障测试样本仍为 500，检验 CI 样本隔离。父/子进程统一从安装包导入 app。

真实探测为 12 个预注册单元，流式与非流式交替各 6 个；每单元独立预算最多 1 次请求，杜绝解析错误隐式扩展计划。请求间隔 7.5 秒、模型超时 120 秒、任务期限 150 秒、已观测 Token 阈值 20000，共享熔断阈值 3。只有 Plan 结构化生成，不读取/修复仓库，不运行目标测试，不创建 PR。触发门控后保留剩余 not_run 单元；未知用量不补零，不自动重发，不替换失败。
