# 修复质量策略与冻结对照方法（2026-10-20）

通用实现先固定为 `a1c5b99abd3f8e58ffd5e2cc551325fe8ef84e8f`，再选择两项新缺陷、执行准入对照并预注册。正式比较使用同一运行时，仅切换任务质量策略。旧版 24 次、17 次严格成功的记录保持不变，不把本轮新增控制组当作旧试验的补跑。

## 第一阶段：补丁协议和完整候选

新增 `REPOPILOT_REPAIR_QUALITY_CHECKS=false`，默认兼容。新任务显式启用时，必须同时使用 `REPOPILOT_RETRY_WORKSPACE_POLICY=isolated` 和 `REPOPILOT_PATCH_TRANSACTIONS=true`；策略版本保存到任务状态，重启后不受服务器开关变化影响。已有任务没有该版本标记，继续旧行为。

质量模式在任何补丁写入前检查规范路径和重复文件编辑，反馈包含 `duplicate_file_edits`、路径、从 1 开始的编辑序号及纠正要求。每个文件仍只能一个 Edit，不自动合并可能重叠或有顺序依赖的修改。模型须用唯一原始片段及其完整替换表示同一文件的全部改动。原有路径、Python 文件边界、语法、大小及原始测试不可变规则继续执行。

新候选必须实际包含新的测试文件及静态可识别测试定义。`contract_tests` 使用精确的 `tests/test_new.py::test_name` 或 `tests/test_new.py::TestClass::test_name`，声明须绑定本候选实际新增的定义。`missing_new_tests`、`missing_test_bindings`、`unbound_test_claim` 会在写入前反馈。独立重试须重新提交完整源码修复与新增测试，不能依赖上一个归档工作区仍存在的文件。

检查只解析 AST，不在宿主机导入或执行目标代码。静态定义和声明绑定不能证明测试被收集或覆盖了语义，因此还需要下一阶段的实际 Docker 证据。动态生成、导入式重导出等测试声明不在该静态准入能力范围内。明确示例 Mock 仅为其已支持的固定示例补齐测试声明，继续标明 mock、零真实模型调用，不扩展为通用修复声明。

## 第二阶段：原始断言和失败到通过证据

质量模式优先呈现原始测试失败，再呈现新增测试失败；通过 AST 提取原有测试断言及来源文本摘要，保留期望语义，避免 pytest 渲染出的运行值替代原始输入/要求。现有原始/生成测试分类、候选身份和失败指纹继续保留。

原来的完整模式已有回归回放。本轮在质量策略开启时，将同一新增测试在原始源码上的回放扩展到三种模式：当前候选测试通过后，复制原始基线及完全相同的新增测试进入独立 Docker 工作区。至少有一个同名用例在原版失败、在候选通过，才是 `demonstrated`。收集错误、超时、缺失/截断证据和两版都通过不构成证明。回放不是对任意需求的完整证明。

不能证明回归时，反馈给修复阶段并消耗现有共享重试预算；不可用的执行证据会阻塞任务，不用模型反复猜测。新测试与源码仍只在 Docker 中执行。原始测试不修改，不增加跳过，不改变断言。

## 第三阶段：审查事实与上下文

质量模式的审查包绑定当前 `candidate_id` 和 `diff_digest`。除了失败用例，也提供按相关性选择的通过用例身份、状态、原始断言和来源文本摘要，避免“未展示通过用例”被误当作“没有覆盖”。同名测试方法按测试类身份绑定。AST 断言属于静态来源信息，不声称每条断言在该次执行中实际到达。

测试事实最多 24 项、事实正文合计最多约 8000 字符，断言截断有标记。源码上下文优先当前改动文件，至多采用原配置一半且不超过 12000 字符，每文件展示不超过 6000 字符；审查 stdout 尾部缩至 2000 字符。文件截断、用例省略及执行器截断明确标注，省略表示未知，不表示不存在。摘要针对规范化读取文本，不冒充 Git blob 或磁盘原始字节摘要。

审查可引用 `Txxx` 测试事实和 `Fxxx` 文件事实；明确引用不存在身份会拒绝批准。此规则不能自动核实全部自然语言审查语义，也不能保证没有幻觉。原有 diff 长度上限继续保留，本轮没有把任意大补丁变成完整语义证明。新增事实和测试回放也有开销，所以只以实际对照测量 Token 和调用数，不预先宣称必然节省成本。

## 第四阶段：72 次冻结对照

六案例 = 原有四项逐字节保留 + 代码冻结后选择的两项新缺陷。新增项来自同一个既有 python-json-pointer 项目，不是未见项目：

- [join 保持左侧子类与工厂分派](https://github.com/stefankoegl/python-json-pointer/commit/09b3cd79442b8ae9be052d114b018621f97df557)，修复前 `16c4c8e33a30e364d94f7a870a6c79916b5f870d`。
- [set 赋值异常契约](https://github.com/stefankoegl/python-json-pointer/commit/7478f3e852a8a5ae6acb9672e2d1f8fb413b8e82)，修复前 `5998f951dcc5ace60f67f35afe6778c445401a07`。

源码、原始测试、参考源码覆盖及隐藏验收记录在语料锁中。模型允许根目录仅为 `corpus/sources`；隐藏验收与参考修复在根目录外。宿主机只读 Git/文本/AST，所有目标测试均在固定 Docker 镜像中执行。六项缺陷版隐藏验收均失败，参考修复的原始套件与隐藏验收均通过；可选 IPython 依赖的原有跳过保持不变。

另有 3 个候选在正式运行前静态排除，原因见 [selection-record.json](selection-record.json)：原始测试收集不完整、修复涉及不支持的无扩展名脚本、上游参考源码覆盖与原有精确参数字典断言不兼容。未将它们算作真实执行、成功修复或正式失败单元。

预注册见 [preregistration.json](preregistration.json)，在首次正式调用前单独本地提交。总矩阵为 6 案例 × 2 策略 × 3 模式 × 每策略 2 重复 = **72 次任务**，每策略 36 次、每模式 12 次。四个区块在偶数案例按 legacy/quality/quality/legacy，奇数案例按 quality/legacy/legacy/quality；每区块旋转模式顺序，两个案例并发。两组同时段交错，不用旧版 17/24 代替控制组。

两组模型、温度、流式用量、上下文配置、超时、候选隔离、补丁事务和预算均相同，仅质量策略与独立任务目录不同。真实模型为用户通道请求/返回别名 `deepseek-v4.1-flash`。模型与测试超时 120 秒、请求间隔 7.5 秒、`max_retries=1`。每任务预算：900 秒、8 请求、100000 已观测 Token、6 沙箱尝试、256 MiB 文件准入和 8 MiB 结果目录。

最多 576 次模型请求是逐任务请求限额之和；已观测 Token 是准入阈值，不是账单或单响应绝对硬限额。评测方的参考对照和独立隐藏验收使用另外的限额账本。原生连接诊断 1 次请求、1215 Token 排除在正式统计之外。

主成功要求：原始测试不变、缺陷基线已重现、当前测试通过、隐藏验收通过、进入待人工审批。全部 72 个单元保留分母；另列当前候选回归证明、已知四案例与新增两缺陷的分层结果、调用、Token、预算与提供方失败。质量策略对三模式施加更严格的新测试证明要求，因此比较的是整套工作流策略，不是单一提示词或纯模型能力的因果效果。

正式调用开始后，不改提示词、运行时、语料、验收或预算；不补跑、替换失败单元或缩小分母。未知用量保持未知并停止自动重发。候选和失败保留，所有任务人工审批保持 pending。评测不写入 GitHub。

## 验证与复现

冻结最终 wheel 完整套件为 **283 passed、2 skipped**，两个跳过来自 Windows 符号链接权限。78 个既有测试/辅助文件保持不变；新建三个测试文件增加 27 个用例，其中 7 项实际 Docker。109 个包内文件与冻结工作区源码及安装字节一致。没有重新验证 sdist。

源码父进程混用旧安装包子进程曾产生 7 个路径一致性断言失败；诊断保留在本地。最终验证预加载已安装新 wheel，父子进程使用同一路径，原断言全部通过。最后的同名测试类身份修正也纳入最终 wheel 完整回归。没有通过修改原有测试绕过问题。

重建 wheel 后安装到固定依赖环境。使用独立仓库副本放置全部测试/固定样本；非 editable 安装时，先 `python -I -c` 导入已安装 app，再调用 `pytest.main`，让进程恢复测试的父子进程都导入同一安装包。目标代码仍只在 Docker 执行。

六案例导出需使用本目录 `spec/spec.json` 及其同目录验收文件，调用 `app.evaluation.historical.prepare(upstream_root, corpus, spec_path)`；CLI 默认四案例注册表不等同于此六案例注册表。克隆项目、镜像离线依赖和初始对照步骤沿用历史评测方法，但应冻结自己重建语料的摘要。

程序化比较入口为 `app.evaluation.historical.run(corpus, output, lock_sha256, settings, repeats=4, workers=2, variants=variants)`。variants 只能包含 legacy、quality，使用同一 Settings 副本，只有 `data_dir` 与 `repair_quality_checks` 不同；两个任务目录必须全新、互不包含且不侵入整个语料目录。设置公共 isolated/patch_transactions/task_budgets 后，将 legacy 的质量开关设 false，quality 设 true。模型密钥经安全进程输入或环境提供，不写入注册记录。

重建可能因平台行尾不同产生新语料摘要，应重新冻结并做对照；仓库中这次已冻结的 JSON/验收文本禁用 Git 行尾转换。语料、原始测试、所有候选、审查来源与用量会在终局再次独立核对。公开小样本、相关重复、手工整理的任务描述及未知训练交集，不能证明生产或未见仓库泛化。代理别名不证明实际底层权重。

本目录方法是固定运行协议；正式结果和发布状态另列报告。新的固定 GitHub 更新需要再绑定人工批准摘要，已有批准只覆盖 `05c00e0`。
