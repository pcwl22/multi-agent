## 实现和验证

实现：默认关闭、按新任务冻结的质量开关；重复编辑路径/序号反馈；完整候选与新增测试声明绑定；三模式同测试原版回放；原始断言优先反馈；当前候选绑定的通过用例/源码事实；有明确截断的审查上下文和无效显式引用拒绝。详见 methodology.md。

最终安装 wheel 完整回归 **283 passed、2 skipped**，两个跳过来自 Windows 符号链接权限。78 个既有测试/辅助文件未改；新建三个测试文件增加 27 个用例，含 7 项真实 Docker。109 个包内文件与冻结源码及安装字节一致。Ruff 和差异空白检查通过。未构建/验证新的 sdist；尚未为本轮未发布提交取得 GitHub CI。

六案例的 24 次原版/参考 Docker 对照全部准入。模型看不到参考源码和隐藏验收。独立审计验证完整矩阵、所有候选原始测试不变、来源摘要、任务预算与用量记录，以及旧 17/24 未改变。没有人工批准修复候选，没有产品侧 GitHub 发布。

执行范围：本轮原始套件是统一 pytest 入口及 TestCase 适配器实际收集的用例。三项 JSON Pointer 案例的 unittest.load_tests 额外 doctest 没有运行，不能声称完整上游原生套件全部通过。文件仍逐字节保留；这项能力边界另记 scope-note.json，没有改动正式输入或分母。
