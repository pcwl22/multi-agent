# 本轮定位结论

六次请求均完整记录用量：输入各 1096、输出各 2048，合计 **18,864 Token**。其中服务端均将全部 2048 输出 Token 报告为 reasoning；通用 SDK 观察到的正文字符数和工具调用数均为 0，结束原因均为 length，没有可解析的 Plan。

实际 HTTP 请求观测确认，B 组只发送 max_tokens；C 组还发送 thinking.disabled。三组均未通过。因而本实验没有支持“只改 Token 参数名即可解决”的假设；即使客户端发出了关闭思考请求，响应仍报告了 reasoning 用量。这不是网络中断或未知用量停止。

证据不能证明代理最终转发了什么，也不能定位是别名固定行为、参数覆盖、后端能力还是其他服务实现造成；不能据此声称官方模型服务异常或 reasoning 一定能关闭。不要把 SDK 正文为空解释为没有生成或零计费。未保存、读取或重建推理正文。
