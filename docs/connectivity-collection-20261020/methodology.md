# 连接核对、原生收集与测试准备事实

本阶段依次补齐连接诊断和只读账本核对、原生测试收集、生成测试准备代码上下文。先做受控验证，再做安装包完整回归，最后冻结独立的小额连接探测；连接验证不能证明修复能力提升，不以新运行替换旧失败。

## 连接诊断和历史账本

允许列表诊断新增严格整数 HTTP 状态码。仅从已知 SDK/HTTP 状态异常的响应读取，保留最多 8 层因果链。响应关联字段只允许 x-request-id、request-id、x-amzn-requestid，最多 512 字符，只保存 SHA-256，不保存原值。保留 SDK 本地版本和本地产生的尝试号、时间及耗时；响应正文、异常文字、URL 和其他头不进入新增故障诊断。状态码能说明这次响应的类别，不能证明代理或上游服务的具体根因。

`python -m app.services.budget_audit TASK_DIRECTORY` 只审计已封存的本地预算 SQLite。路径经过仓库检查；文件大小受限，以只读 immutable/query_only 模式打开，并拒绝 WAL/SHM/journal 伴随文件，检查完整性、边界模型、计数与预留一致性，前后比对文件 SHA-256。不更新 last_time，不完成预留，不退回配额，也不自动重发。仅适用于已停止的工作进程，不是在线账单对账服务。

旧 probe-01 用量未知，probe-02 仍有一个待确认模型预留。当前证据没有提供方逐请求回执或账单接口，不能确认两项计费。没有据此把 0 个已观测 Token 当成零账单，也没有对原请求补跑或清除预留。旧 12 单元中的 10 项未执行状态保持不变。

## 全新连接探测

新增 `python -m app.evaluation.connectivity --plan FILE --sha256 DIGEST --output FRESH_DIRECTORY`。计划内容摘要和全部 app Python 文件摘要必须匹配；密钥由隐藏输入进入进程，不写入计划。固定顺序为非流式一次、流式一次，串行且总预留上限 2 次，各有独立持久预算。45 秒模型超时、60 秒任务期限、每项 4096 已观测 Token 阈值及最多 4096 输出 Token。已观测 Token 阈值不是绝对计费上限或金额硬限。

首次失败、缺失用量或预算停止后，不再发送下一项；SDK 隐式重试关闭，解析重试无法越过单项 1 请求预算。输出目录必须全新，启动前先保存完整计划分母和未执行状态；每项调用前保存未确认意图。中断遗留意图和预留，只能另行只读审计，不能重开原目录执行。这是两个 smoke 探测，不是持续可用性、长上下文或代码修复评测。

本轮人工执行额外使用封存的独立进程控制器，整批 135 秒硬时限；超时只终止它直接创建的子进程，保留未确认记录，不重试。45 秒 SDK 网络超时不是整次流式生成的绝对时限，60 秒任务预算在边界检查；135 秒为本轮控制器的进程时限。该控制器的正常退出与超时终止路径由受控本地进程验证，不冒充模型连接证据。

## 原生测试收集

`repopilot-eval-historical prepare --collection-protocol native-v2 ...` 显式生成新版语料，旧默认 legacy 行为及旧冻结语料保持不变。通过标准 TestLoader.loadTestsFromModule 调用上游 load_tests，支持其增加 doctest、删除或替换默认套件。完整 native suite 按原生顺序执行一次，保留类级和模块级初始化/清理；pytest 参数化测试报告缓存的逐测试结果。

每个适配器额外有一个完整性测试，用来暴露 loader/fixture 错误并记录原生 ID 清单。这个额外测试不能冒充上游测试数量。报告原生 ID 和结果清单，与独立 `unittest` 入口在相同 Docker 镜像中的清单逐项比较。空套件或重复 ID 拒绝运行；当前实现不承诺任意自定义 runner 和重复身份测试兼容。

本次六项历史案例使用全新 lock，不覆盖旧语料。四个原生入口案例的修复前和参考修复后，共 8 个快照独立核对；三个 JSON Pointer 快照版本分别新增纳入各 5 个原先遗漏的 doctest。全部目标导入、收集和测试执行都在禁网、限资源、只读挂载、非 root 的 Docker 中进行。六例各四项基线/参考与隐藏验收控制重跑，参考修复是评测控制，不算模型修复。

## 生成测试的准备事实

在既有质量 V2 显式启用时，失败反馈额外提供最多 4 个 NEW 测试函数的源码摘要、摘录、调用表达式、字面量类型与行号，序列化事实预算 6000 字符。原始源码只经过路径检查及 AST 分析，不在宿主机导入。字面量类型保留 bytes/str、负号和 Unicode 原文。

这些是静态源码事实，不是已执行调用顺序，不能由此声称公共 API 已触发，也不自动断言哪个期望错误。提示结合 Docker 失败、原 issue、源 API 默认值检查准备参数、编码和 Unicode 预期。受控模型的 unsigned pack 和 bytes.encode 失败场景必须通过重试后真实 fail-to-pass 见证才能进入人工审批；不修改原测试、不放宽见证规则、不把受控结果说成真实模型提升。质量开关继续默认关闭。
